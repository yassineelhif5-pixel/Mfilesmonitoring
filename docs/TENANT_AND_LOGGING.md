# MFCMP - Tenant model and logging

## Tenant isolation
- Each registered M-Files vault is provisioned with exactly one logical tenant.
- Existing vaults are backfilled by migration `202611170001_TenantsServiceAccountsAndLogs`.
- The tenant is resolved by VaultId; log search is scoped by TenantId server-side.
- A tenant owns its service-account registrations and monitoring logs.

## Service accounts
- Register one or more M-Files technical accounts for a tenant.
- Select one primary enabled account; otherwise the first enabled account is used.
- Credentials and tokens are never stored in SQL or submitted to the portal. SQL stores only the Azure Key Vault secret URI.
- Secret JSON for Credentials: `{"username":"svc_login","password":"..."}`
- Secret JSON for Token: `{"token":"...","pluginName":"optional","configurationScope":"optional"}`
- The account name is a traceability label. Ensure the username in the Key Vault secret corresponds to that account.
- The provider updates LastUsedAtUtc when it resolves the primary account.

## Log categories
- CONNECTIVITY: successful connection and connectivity checks.
- AUTHENTICATION: account or token authentication errors.
- PERMISSIONS: authenticated identity could not access the vault.
- ERROR: other failed diagnostics.
- CONFIGURATION: tenant or service-account configuration events.
- METRICS: metric collection events/errors (collection errors currently also create incidents).
- SYSTEM: reserved for portal/system lifecycle events.

## Log sources
- MFCMP: generated by this portal (manual connection tests, scheduled health checks, account registration).
- MFILES_AUDIT and MFILES_SERVER are reserved source filters for future ingestion.
- Do not interpret MFCMP logs as native M-Files server/audit logs. Native logs require a supported M-Files audit/export interface or an approved log feed and have not yet been integrated.

## Targeted log search API
`GET /api/tenants/{tenantId}/logs`

Optional query parameters:
- `category`, `level`, `serviceAccountId`, `source`
- `fromUtc`, `toUtc` (ISO-8601 UTC)
- `search` (event, message, error code, correlation ID)
- `page`, `pageSize` (maximum 200)

The API always adds `TenantId == {tenantId}` to the database query. It does not accept an arbitrary VaultId for a log search.

## Tenant and service-account APIs
- `GET /api/tenants/by-vault/{vaultId}`
- `POST /api/tenants/{tenantId}/service-accounts`
- `PATCH /api/tenants/{tenantId}/service-accounts/{accountId}`

## Migration / deployment
Apply EF Core migrations before deploying the updated application:
`dotnet ef database update --project backend/src/MFCMP.Api`

Take a database backup first. The migration creates tenants for existing vault records and adds service-account and log tables. It does not import historic M-Files native logs.
